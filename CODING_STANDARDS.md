# Coding standards

What a reviewer checks a diff against (`/code-review`'s Standards axis).
AGENTS.md says where work belongs and how to build it; this file says
what a change must look like to merge. Anything `cargo fmt`, clippy or a
test already enforces is not repeated here.

## The call site comes first

DX is the product: the code a user writes and the code rok generates for
them.

- **Ergonomics.** Flag a change that makes a user write boilerplate, add a
  surprising bound (a derive that suddenly needs `Clone`), or spell a long
  path at the call site. Generated code is held to the same bar as
  hand-written code.
- **Names say what a thing is.** Public methods, types and `rok.toml`
  values never carry another framework's name (`paginator`, not
  `laravel`). Comparing to a framework in prose is fine.

## Workspace shape

- **One binary, `rok`.** No crate other than `rok-cli` gains a `[[bin]]`.
- **Libraries never depend on `rok-data-cli`**, and only `rok-data-core`
  depends on sqlx.
- **The `rok sqlc` grammar lives in the engine's `cli.rs`.** `rok-cli`
  forwards tokens verbatim; a re-declared flag or subcommand there is a
  defect.
- **Fixture, example and template crates stay out of the workspace**:
  listed under `exclude`, each with its own `[workspace]` table.
- **No dependency outside crates.io**, except path dependencies inside
  this repository: a path into a sibling checkout neither builds in CI
  nor publishes.
- **Files stay under ~600 lines.** A change that adds a new kind of
  behaviour to a large file splits it first, by responsibility.

## Generated and template code

- **Marker headers.** Every matcher of generated or scaffolded content
  accepts both `@generated by rok-sqlc` and `@generated by rok-data-sqlc`.
- **Snapshots refresh only through `ROK_DATA_SQLC_UPDATE_EXPECTED=1`**.
  A hand edit to `milestone-1.txt`, a template's `src/db/` or another
  recorded output is a defect, even when it matches.
- **The templates' shared files stay byte-identical** across actix and
  axum (`tests/template_drift.rs` lists them). A change to one is made to
  both.
- **Template code passes the template's own lints on the CI's MSRV
  (Rust 1.94)**: no `unwrap`/`expect`/`panic` outside tests, every public
  item documented, the selected pedantic lints. A newer local clippy
  accepts things 1.94 refuses: doc comments write product names inside
  backticks or reword them.
- **Capabilities are compiled in and inert until their environment
  variable is set** (workspace ADR 0023). A vendor-specific integration
  is a recipe, not template code.

## Errors, secrets and safety

- **Errors carry what the caller needs.** A configuration error names the
  variable; a CLI error says what to do; nothing panics on user input.
- **Secrets never reach a log, a `Debug` or an error message.** Summaries
  print a secret's length, a URL's password as `<redacted>`.
- **Destructive operations ask first** (typed name or `--yes`) and refuse
  the project's own database without `--force`.
- **SQL takes parameters**, never formatted user input.

## Docs move with the code

- **`docs/cli-reference.md` changes in the same diff as any grammar
  change.** It is contract.
- **A user-visible change adds a line under `CHANGELOG.md`'s
  `[Unreleased]`** (and the engine's own CHANGELOG for engine changes).
- **A Rust sample in a guide is either quoted from a compiled file**
  (`<!-- source: <path> -->`, checked by a test) **or marked
  `<!-- not compiled: <reason> -->`.**
- **A new or renamed page under `docs/` updates `docs/llms.txt`** or
  `docs/README.md`.
- **A cross-crate decision gets a workspace ADR; an engine decision an
  engine ADR.** Cite "workspace ADR NNNN" or "engine ADR NNNN" wherever
  the number alone is ambiguous.

## Tests

- **A bug fix carries the test that was red before it.**
- **DB-backed tests skip with a printed note** when their URL is unset,
  never silently.
- **Each behaviour is tested at its seam**: the engine's output in the
  engine, the `rok` binary's behaviour in `rok-cli/tests` (workspace
  ADR 0003).
