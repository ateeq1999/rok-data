# Architecture

Feature-first, four layers: **ApiClient → Repository → Cubit/BLoC → View**.
Dependencies flow down; events flow up.

```
View            (widgets, forms, navigation)
  │ context.read<Cubit>()
  ▼
Cubit / BLoC    (UI state machine; emits sealed states)
  │ calls
  ▼
Repository      (the App's use of the API; throws the client's ApiException)
  │ calls api.<tag>.<operation>(...)
  ▼
ApiClient       (clients/dart, generated by `rok gen` from apps/api's openapi.json)
  │ reads the bearer token from
  ▼
AuthService     (the client's Session: token + user in secure storage)
```

## Why these layers?

- **ApiClient** is generated: typed calls, the models (`AccountResponse`,
  `LoginResponse`...) and `ApiException`. The App writes no HTTP code and no
  JSON mapping; a contract change reaches it through `rok gen`.
- **Repository** says what the App does with the calls: signing in saves
  the session and reads the user, changing the password ends the session,
  the two-factor calls keep the session on a wrong code. Cubits mock it.
- **Cubit/BLoC** owns UI state transitions. Never imports the client's
  transport.
- **View** owns widgets + navigation side effects; it reads repositories
  only to build a cubit.

## Dependency injection

No service locator. `main.dart` builds the graph bottom-up and hands it to
the `flutter_bloc` provider tree:

```dart
final authService = AuthService();
final api = ApiClient(baseUrl: AppConfig.apiUrl, session: authService);
final authRepository = AuthRepository(api, authService);
final userRepository = UserRepository(api);
```

Per-screen cubits are created inside their `GoRoute` builder with
`context.read<Repo>()` ([app_router.dart](../lib/app/core/router/app_router.dart)).

## Auth state & routing

[AuthBloc](../lib/app/modules/auth/auth_bloc.dart) is the single source of
truth for who is signed in:

- `AuthInitial` / `AuthLoading` — hydrating, stay on splash
- `AuthAuthenticated(user, token)` — home + protected routes
- `AuthUnauthenticated` — sign-in + guest routes

The router re-evaluates its `redirect` on every emission, so signing out
(or the API rejecting the token: the client calls `AuthService.expired`,
which signs out) drops you back to `/sign-in` without explicit navigation.

The API answers a sign-in with a session (`TokenResponse`) or, for an
account with two-factor on, a pending token (`LoginResponsePendingToken`):
`SignInCubit` sends the second to `/two-factor`, which posts it with the
authenticator's code. The API has no refresh token: an expired session
signs in again.

## Errors

Every failed call throws the client's `ApiException`: `status` (0 when no
answer came), `code`, `message`, and a `422`'s `details` (`FieldIssue`s by
field). Cubits catch it and emit a `*Failure` state; forms show
`e.fieldErrors` (one message per field, keyed by the API's field names,
such as `new_password`) through `TextFormField.forceErrorText`.

## Persistence

| Data | Store | Location |
|---|---|---|
| Bearer token + user JSON | `flutter_secure_storage` | [auth_service.dart](../lib/app/services/auth_service.dart) |
| Theme preferences | `SharedPreferences` | [theme_cubit.dart](../lib/app/modules/theme/theme_cubit.dart) |
| HydratedBloc state | Application docs dir | initialised in [main.dart](../lib/main.dart) |

Never put tokens in `SharedPreferences` — it's not encrypted.

## Testing

| Layer | Tool | Example |

`test/support/api.dart` builds a client over a fake API and the API's JSON
shapes. Widget tests must wrap the tree in
`RepositoryProvider<FeatureFlags>.value(...)`: a view that reads flags
throws `ProviderNotFoundException` otherwise.
