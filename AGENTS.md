# AGENTS.md — working inside the rok-data workspace

This file tells agents (and humans joining the tree) what this
repository is, which rules keep its shape intact, and where work
belongs.

## The one-paragraph version

`rok-data` is a Cargo workspace consolidating four repositories
(audit: `docs/migration-audit.md`). The runtime lives in
`rok-data-core` (+ `rok-data-macros` + the `rok-data` facade), the model
crate generator in `rok-data-codegen`, the resource-module generator
engine in `rok-data-sqlc`, and the only binary is `rok` in `rok-cli`.
Libraries never depend on `rok-cli`; the CLI delegates to library
functions; sqlx is depended on only by `rok-data-core`.

## Where changes belong

| Task in front of you                            | Touch                                                            |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| New runtime capability (query builder, Db API)  | `crates/rok-data-core/src/...`; re-export if useful via facade     |
| New derive or attribute macro                   | `crates/rok-data-macros`; keep it thin, compile-checked via facade |
| Model-crate generator change                    | `crates/rok-data-codegen` + its tests; maybe `examples/sqlgen`     |
| Resource-module/OpenAPI generator change        | `crates/rok-data-sqlc/src/...` + engine tests                     |
| `rok sqlc …` behavior change                    | **the engine's** `src/cli.rs` — grammar lives there, not in rok-cli |
| CLI wiring / output formats / new root commands | `crates/rok-cli/src/{cli,commands,context,output,config}.rs`       |
| Migration file format change                    | `crates/rok-data-core/src/{migration,migration_file}.rs` both      |
| Fixtures (compile crates)                       | `crates/rok-data-sqlc/tests/{api-app,fixture-app,modules-app}` — excluded from the workspace; they manage own deps |

## Invariants (break them and something is wrong; fix the thing you broke)

1. `cargo fmt --all` clean, `cargo clippy --workspace --all-targets -D
   warnings` clean. The engine's `Cargo.toml` spells its lint set out
   (it does not inherit the workspace lints; see ADR 0007) — keep the
   two consistent when changing either.
2. Only one binary target in the whole workspace: `rok`. Regenerating
   the example is `cargo run -p rok-data-codegen --example regenerate`.
3. `rok sqlc` tokens are forwarded verbatim to
   `rok_data_sqlc::cli::run_from`. Never re-declare that grammar in
   rok-cli; the help text the user sees must match the engine's tests.
4. Test suites that drove the old `rok-data-sqlc` binary live in
   `rok-cli/tests` and spawn `CARGO_BIN_EXE_rok` with `"sqlc"`
   prepended (ADR 0003). Library suites stay in the engine crate. Do
   not "fix" this by re-adding a binary to rok-data-sqlc.
5. Generated/scaffolded content is recognized by marker headers; every
   such matcher accepts the legacy `@generated by rok-sqlc` and the
   current `@generated by rok-data-sqlc` (ADR 0005).
6. Both migration file formats are loadable (`migration_file`): pairs
   and single-file sections; versioned names `NNNN_name` required
   (ADR 0004).
7. Fixture/example crates stay listed in workspace `exclude` and keep
   their `[workspace]` tables. Do not add them as members.
8. Licensing for new files: SPDX headers acceptable; workspace default
   is MIT OR Apache-2.0. The sqlc engine files carry their provenance.

## Conventions pulled from the original repos (kept deliberately)

- Journal table `_rok_data_migrations`; states `applied|pending|edited|
  unknown`; checksum drift is fatal except with `--json` consumers
  reading `drift`.
- Codegen config `rok-data.toml` under `[gen]`, keys
  `rok_data_version` (semver pin of the facade crate) and
  `rok_data_path` (path dep) are mutually exclusive; flags beat the
  file.
- PostgreSQL-only; no abstraction layer for other databases (deliberate
  scope, not an omission).

## Building and testing

```console
$ cargo test --workspace --all-targets        # everything, ~2-3 min
$ cargo test -p rok-data-sqlc --lib           # engine unit suite (236)
$ cargo test -p rok-cli --test cli            # sqlc CLI suites via the rok binary
$ cargo test -p rok-data-sqlc --test module_fixtures   # corpus (needs rustc ≥ fixture MSRV)
```

DB-backed suites skip with a printed note when
`DATABASE_URL` / `ROK_DATA_SQLC_TEST_DATABASE_URL` are unset — the
skip is honest (printed, never silent).

## Docs discipline

- ADRs under `docs/decisions/`: add one for any decision a reader
  would otherwise have to reconstruct from git history.
- The CLI reference (`docs/cli-reference.md`) is contract; update it in
  the same PR as any grammar change.
- The milestone/expected snapshots in the engine (`milestone-1.txt`,
  templates' generated files) refresh only via the sanctioned
  `ROK_DATA_SQLC_UPDATE_EXPECTED=1` runs — never by hand-editing.
