# rok-data for coding agents

The toolchain was built to be driven by a machine: one truth, one command
per step, one JSON document when a program asks for it. This page is the
contract surface an agent needs — paste it whole into a coding agent and
it can scaffold, generate, and verify a rok-data project without a human
translating.

## The mental model, in three sentences

The project's **schema directory** (`schema/` or `migrations/`) is the
only source of truth: plain `*.sql` files are the schema as it is now,
and the `NNNN_name.up.sql` / `.down.sql` pairs beside them are the
history. `rok gen` turns that directory into a Rust data layer
(`src/db/**`) and API features (`src/features/**`); `rok gen --migration
NAME` stages the difference since the last staged pair. `rok gen check`
writes nothing and exits **1** when the generated code is out of date —
that is the CI gate, and the agent's freshness oracle.

## JSON contracts

`--json` switches the database commands to a machine contract: one JSON
document on stdout, *nothing else* there (progress and prose go to
stderr).

```sh
rok migrate status --json
```

```json
{
  "migrations": [
    { "version": 1, "name": "create_notes", "state": "applied",
      "checksum": "9f2a31b8c04d5177", "drift": false }
  ]
}
```

`state` is one of `applied | pending | edited | unknown`; `drift` is
`true` when the file's checksum no longer matches the journal — drift is
fatal to apply without a deliberate decision.

```sh
rok db check --json       # {"connected": true, "server_version": "PostgreSQL 17.2"}
rok gen check --json      # one JSON object on stdout; process exit code carries the verdict
```

## Exit codes

| Code | Meaning |
| ---- | ------- |
| 0 | success, `--help`, `--version` |
| 1 | runtime failure anywhere — bad URL, drift, a check that failed; also *usage* errors inside `rok sqlc …` (the engine's historic behavior, preserved) |
| 2 | usage errors at the root (clap) |

`--force` overwrites files the generator did not write; `--strict` turns
warnings (a skipped table or query) into failures; flags beat every
settings file.

## The agent's loop

A canonical schema-change loop, safe to run unattended:

```sh
# 1. Edit the schema (the only truth).
$EDITOR schema/0002_add_posts.sql                 # or migrations/0002_… pairs

# 2. Ask for the plan first; write nothing.
rok gen --dry-run

# 3. Stage the schema delta as a migration pair + generate the code.
rok gen --migration add_posts

# 4. Verify generated code is fresh (CI mode).
rok gen check                                      # exit 0 = fresh

# 5. Apply to the database and confirm.
export DATABASE_URL=postgres://…
rok migrate up && rok migrate status --json
```

Rules the loop relies on:

- Files under `src/db/**` and `src/features/**` carry `@generated by
  rok-data-sqlc…` headers (three marker generations are recognized).
  Hand-edits there are preserved by *your* discipline, not the tool's —
  change the schema, not the generated files.
- `rok init` writes every file **once, never rewritten**: a second run
  only fills what is missing. Treat its output as scaffolded, not live.
- The generated project's templates ship their own `AGENTS.md`, pinned
  to `rok sqlc check-arch`'s layout rules — an agent working inside a
  generated project already has its instructions.
- Destructive migration steps (a dropped column, a narrowed type) refuse
  to stage without `--allow-destructive`; `--rename old=new` preserves
  identity across renames instead of drop+create.

## Companion agent skills

This repository ships five OpenCode-discoverable skills under
[`.agents/skills/`](../.agents/skills/) (each a `SKILL.md` with trigger
richness in its description):

| Skill | Fires when |
| ----- | ---------- |
| `rok-data` | any work in this workspace — the router: which page, which ADR, which crate |
| `rok-data-init` | scaffolding or regenerating a service with `rok init` / `rok gen` |
| `rok-data-models` | authoring hand-written or generated model code (`#[derive(Model)]`, the Model chain, `ModelWrite`) |
| `rok-data-migrations` | migration design, staging, drift, the status JSON contract |
| `rok-data-sqlc` | engine work inside `crates/rok-data-sqlc` (templates, API features, check-arch, engine ADRs) |

A pre-consolidation skill, `rok-rust` (the original `rok-fluent`
project), still circulates globally — treat it as source-history, not
authority.
