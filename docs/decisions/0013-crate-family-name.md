# ADR 0013: one crate family — the name stays `rok-data`

Date: 2026-10-19 · Status: accepted (amended 2026-10-21)

## Context

The workspace consolidated four repositories (see
`docs/migration-audit.md`), but kept the consolidation name `rok-data`
across all crates while the surviving runtime lineage (ADR 0001) and its
original published facade was **rok-db**. Running two family names —
runtime as `rok-data-core`/`rok-data`/`rok-data-macros` and engines as
`rok-data-sqlc`/`rok-data-codegen` — reads as two projects and quietly
suggests old lanes still exist.

## Decision (2026-10-19)

At 0.2.0 (the breaking-change window ADR 0009 already claims), every
workspace crate adopts the **rok-db family**:

| crate | new name | was |
|---|---|---|
| facade | `rok-db` | `rok-data` (reclaims the runtime's original published name) |
| runtime | `rok-db-core` | `rok-data-core` |
| derives | `rok-db-macros` | `rok-data-macros` |
| engines | `rok-db-sqlc`, `rok-db-codegen` | `rok-data-sqlc`, `rok-data-codegen` |

Consequential renames and their policy anchors:

- Generated marker headers gain a third accepted form
  (`@generated by rok-db-sqlc`) alongside both ADR 0005 legacy forms —
  all three accepted forever.
- The engine test env var becomes `ROK_DB_SQLC_TEST_DATABASE_URL`
  (CI configs renamed in the same change; the old name stops being
  read — one clean cut at the 0.2.0 window).
- The migration journal table `_rok_data_migrations` is **not** renamed:
  it is deployed DB surface (ADR 0004), and renaming it would break
  every installed project.
- `rok-data.toml` / `rok-data-sqlc.toml` stay readable compat aliases
  under ADR 0011; `rok.toml` remains the canonical file name.
- Release gate: verify crates.io name availability/ownership for
  `rok-db`, `rok-db-core`, `rok-db-sqlc`, `rok-db-codegen`,
  `rok-db-macros` **before** tagging, then publish in dependency order
  per ADR 0008.
- The `rok` binary name is untouched (ADR 0002); only crates and
  marker/env surfaces renames.

## Amendment (2026-10-21): the rename was not taken

The 0.2.0 window was spent on the unified pipeline instead: the ORM
chains in the generated data layer, the front door (`rok init`,
`rok gen`), the axum API backend and the vertical slice. The rename
never landed, and the repository therefore contradicts the decision
above in three places. This amendment records what was actually
decided — **the family stays `rok-data`** — and why:

- **The crates stay `rok-data*`**: `rok-data`, `rok-data-core`,
  `rok-data-macros`, `rok-data-sqlc`, `rok-data-codegen`. The rename
  was never taken, so nothing in the tree, the docs or the published
  crates says `rok-db`.
- **The env var stays `ROK_DATA_SQLC_TEST_DATABASE_URL`**: the engine's
  DB-backed suites read it, and it is the name CI and `AGENTS.md` use.
- **The markers stay two**: `@generated by rok-sqlc` (the legacy form)
  and `@generated by rok-data-sqlc` (ADR 0005). No
  `@generated by rok-db-sqlc` form exists, and none is accepted.
- **The journal table and the binary stay**: `_rok_data_migrations`
  (deployed DB surface, ADR 0004) and the `rok` binary (ADR 0002) were
  never in question.

Why: a crate rename is a breaking change that must land in one
release, with the crates.io names checked before the tag (ADR 0008) and
every dependent path, doc link and generated fragment moved in the same
change. Doing it halfway is worse than not doing it: the tree would
carry two families and the release would publish names nobody
generates. The 0.2.0 window had room for exactly one breaking change,
and it went to the pipeline.

Consequences:

- The rename is **deferred past 0.2.0** (Phase 0.5 of
  `docs/unified-pipeline-plan.md`), with the reason recorded there.
- The 0.2.0 release publishes the `rok-data*` crates — the names in
  `AGENTS.md`'s Releasing section — and the crates.io availability
  check covers those names, not the `rok-db` ones.
- Should the rename happen later, it happens whole: crates, dependency
  paths, doc links, the env var, the marker forms and the generated
  dependency fragments move together, in one release.
- No crate named rok-fluent or rok-orm is ever published; the `*_src`
  sibling clones remain the historical record only.
