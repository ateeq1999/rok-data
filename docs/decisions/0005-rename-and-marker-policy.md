# ADR 0005: the rename policy — mechanical renames plus compatibility markers

Date: 2026-10-19 · Status: accepted

## Context

Three tools acquire one name (`rok`). Renaming "in spirit" (different
wording per file) would make grepping impossible, while *editing all
historical text* would lose which strings were the tool's own contract
versus prose. Generated files also embed the tool's name in their first
line, and existing project trees are full of those files.

## Decision

Mechanical replacements (in this order), applied by script during the
port:

| Original            | New                          |
| ------------------- | ---------------------------- |
| `rok-db`/`rok-sqlc` | `rok-data`/`rok-data-sqlc`   |
| `rok_db`/`rok_sqlc` | `rok_data`/`rok_data_sqlc`   |
| `ROK_*_` env prefix | `ROK_DATA_*`                 |
| journal table       | `_rok_data_migrations`       |
| codegen config      | `rok-data.toml` (`[gen]`)    |
| engine config file  | `rok-data-sqlc.toml`         |

The compatibility part is not mechanical: wherever code *recognizes*
generated files, it must accept **both** generations of marker:

- the current `@generated by rok-data-sqlc` header, and
- the legacy `@generated by rok-sqlc` header.

`is_generated`-style checks exist in three places (the writer's staleness
check, the engine's `init --template` skip, and the moved test helpers)
and all three accept both. Existing projects therefore keep working
until the next regeneration, when their files graduate to the new
header.

## Consequences

- `rg "rok-sqlc"` in the workspace returns only intentional matches

  (legacy-marker constants and their comments; LICENSE attribution).

- Regeneration changes one line in every generated file (the header) —

  tooling that diffs generated output sees it as drift, which the
  `--check` modes report; the sanctioned refresh is rerunning the
  generator (or the fixtures' `ROK_DATA_SQLC_UPDATE_EXPECTED=1`).

- Milestone records and snapshots (the actix template's embedded

  generated files, `tests/openapi_off/milestone-1.txt`) were refreshed
  exactly once, right after the rename.

- The changes the rename produced in *prose* (engine docstrings such as
  "aliases and column names rok-data-sqlc generated") were reviewed and
  corrected where a mechanical rule had mangled the wording.
