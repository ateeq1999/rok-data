## Layout (engine = `crates/rok-data-sqlc`)

- `src/cli.rs` — the engine's clap grammar. `rok sqlc …` forwards its
  tokens here verbatim **without re-declaring them in rok-cli**; engine
  help text, aliases and exit codes (usage errors exit 1) are what its
  tests assert. A grammar change updates:
  1. the engine's `cli.rs` + engine tests,
  2. `docs/cli-reference.md` in the same PR (contract),
  3. the mirror suites in `crates/rok-cli/tests/` (they spawn
     `CARGO_BIN_EXE_rok` with `"sqlc"` prepended — workspace ADR 0003).
- Emission: `src/generator/…` (db modules, api/{actix,axum,framework},
  shared), templates and generated code contract via the marker headers
  (`@generated by rok-data-sqlc`, legacy `@generated by rok-sqlc`
  accepted by every matcher — workspace ADR 0005).
- Templates: `templates/{actix-api,axum-api}/` — workspace-**excluded**
  crates with their own `[workspace]` and dependency pins; never added
  as members, never hand-refreshed (see snapshots below).

## Test loops

| Suite | Command | Notes |
| ----- | ------- | ----- |
| engine unit | `cargo test -p rok-data-sqlc --lib` | the big unit suite (330ish) |
| corpus | `cargo test -p rok-data-sqlc --test module_fixtures` | rustc ≥ fixture MSRV needed |
| CLI mirror | `cargo test -p rok-data-cli --test cli` | suite-level sqlc CLI tests |
| fixtures/examples | their own crates (`tests/{fixture,api,axum}-app`, `docs/examples/*`) | run inside the directory; excluded from workspace builds |

Expected/`milestone` snapshots and template outputs refresh **only** via
the sanctioned env run — never hand-edit:

```sh
ROK_DATA_SQLC_UPDATE_EXPECTED=1 <the sanctioned regeneration command>
```

…then review the diff like code: templates' recorded diffs are CI
assertions (rustfmt-clean, the template's pedantic lints
`deny(missing_docs)`, no `unwrap`/`expect`/`panic`, `check-arch`,
`rok init --template …` copies).

## check-arch

`rok sqlc check-arch` (alias `a`) polices the generated layout, engine
ADR 0016: rule 1 names the configured framework — it reads `[api]
framework` from the same config generation does; `actix_web` default
(texts byte-identical, pinned by tests), `axum` polices axum over the
same allowed-file set. Rule texts have one source per framework — edit
the source, not a rendering.

## ADR discipline (engine series)

Engine ADRs live in `crates/rok-data-sqlc/docs/adr/` and keep growing
forward (0026 newest as of 2026-10). ADRs 0019–0022 are *imported* from
rok-sqlc and each carries "Formerly rok-sqlc ADR NNNN"; an imported or
new engine ADR never renumbers anything and never claims a workspace
number (workspace ADR 0016). Guides and per-crate docs:
`crates/rok-data-sqlc/docs/`.

## Conventions and presets

The unified `[conventions]` key set (preset `rok` default; an empty
string disables a key) feeds both the ORM derive generation and the
engine's conventions/preset machinery — one key set, two consumers
(workspace ADR 0015). When touching anything there, change neither side
alone: the presets' golden outputs are pinned in the engine unit suite.
