## The workspace in one breath

Six crates; one runtime dependency rule; one binary.

- **`rok-data-core`** — sqlx 0.9 (PostgreSQL-only) runtime: `Db`, the
  `Expr`/`Select` builder, `Model`/`ModelWrite` traits, migrations +
  introspection, error/metrics/tenant/validate/web/wire.
- **`rok-data-macros`** — proc macros: `#[derive(Model)]` (columns,
  relations, scopes, trait impls), `FromRow`/`DbEnum`/`DbNewtype`,
  `#[rok_data::test]`.
- **`rok-data`** — facade: the only dependency applications take.
- **`rok-data-codegen`** — whole-crate generator + the
  `--migration` diff/staging engine (also drives `rok gen --migration`).
- **`rok-data-sqlc`** — the resource-module engine (its `rok sqlc …`
  grammar, templates, API features); the models-live-here engine since
  0.3.0.
- **`rok-cli`** → publishes as `rok-data-cli`, binary `rok`. Merge gift:
  help text for the `sqlc` subtree is the engine's own clap grammar,
  forwarded verbatim.

## Citing ADRs (the numbering collides on purpose)

Two independent series start at 0001; nothing is ever renumbered.

- **workspace ADR NNNN** → [`docs/decisions/NNNN-…md`](../../../docs/decisions/), currently 0001–0021.
- **engine ADR NNNN** → [`crates/rok-data-sqlc/docs/adr/NNNN-…md`](../../../crates/rok-data-sqlc/docs/adr/); keep growing forward only.
- In prose, a bare "ADR NNNN" is ambiguous: write the qualifier
  ("workspace ADR 0010"). In doc comments the short form is the space's
  convention — qualify when the file could land in either crate.

## Marker and version facts that bite

- Generated/scaffolded files are matched by marker headers; every matcher
  accepts `@generated by rok-data-sqlc` **and** legacy `@generated by
  rok-sqlc` — when you touch one, accept both (workspace ADR 0005).
- Generated projects pin the facade by **`rok_data_version` (semver) xor
  `rok_data_path` (path dep)** — mutually exclusive keys under
  `[generate]` in `rok.toml`; flags beat the file.
- The journal table `_rok_data_migrations` and the `rok` binary name are
  deployed surfaces: they do **not** rename with a crate family rename.
- The workspace version lives in the root `Cargo.toml` `[workspace.package]`;
  a tag must equal it and needs a `CHANGELOG.md` `## [X.Y.Z]` section,
  or the release workflow fails (workspace ADR 0008).

## Release-prep quick loop

1. `cargo fmt --all && cargo clippy --workspace --all-targets -D warnings`.
2. `cargo test --workspace --all-targets` (DB suites skip honestly
   without `DATABASE_URL`; the engine's `module_fixtures` needs a
   rustc ≥ the fixtures' MSRV).
3. Changelog `## [X.Y.Z]` == tag == workspace version; crates.io names
   checked before tagging; the CLI publishes as `rok-data-cli`.
4. Full details in the root `AGENTS.md` §Releasing — read it, do not
   improvise the sequence.
